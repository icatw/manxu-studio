# AI 生成管线

## 模型职责

- **文本模型**：故事扩写、角色/场景档案、分镜拆解、局部文本改写和图像提示词草拟。
- **图像生成/编辑模型**：角色参考图、场景参考图和分镜画面。
- **视觉理解模型（可选）**：检查图像与文字设定的明显偏差，作为提示而非自动裁决。
- **语音/视频模型**：不属于预制作主链路，后续独立评估。

供应商通过后端适配层接入。具体模型能力、参考图限制、输出尺寸、异步接口和地域可用性需要在接入时依据当前官方文档验证。

## 生成步骤

### 角色/场景设定

输入：当前故事版本、题材/画风偏好、已有用户补充。输出：经过 Pydantic 校验的结构化设定草稿。用户编辑并确认后，生成一个不可变资产版本。

### 分镜脚本

输入：故事版本、已确认角色/场景版本、画幅、分镜数量和节奏偏好。输出：有序分镜列表。每格包含剧情作用、场景、镜头、动作、情绪、对白和画面提示词。

### 图像生成

输入：单格当前版本、提示词、画风、关联角色/场景参考资产和画幅。输出：一个或多个候选图像资产。生成任务保存完整输入快照；用户选择后将某个候选设为当前图像。

### 单格修改

输入：当前分镜和图像版本、用户修改指令、需要保留的元素、重新引用的资产版本。输出：新的候选版本，不覆盖旧版本。

## 结构化输出

文本模型输出必须通过后端 schema 校验。解析失败时只做有限的格式修复重试；内容仍无效则任务失败并保留错误摘要，不将原始模型文本静默当作合法领域数据。

## 任务执行与可恢复性

1. API 验证用户输入和目标实体。
2. 保存 `queued` 任务和输入快照，返回任务 ID。
3. Worker 调用供应商并更新 `running` 状态。
4. 长任务通过供应商轮询/回调获取结果；结果复制到持久对象存储。
5. 校验产物后保存并标记 `succeeded`；失败记录可展示的错误摘要。
6. 客户端可离开页面；重新进入后按任务 ID 恢复状态。

普通重试建立新任务并记录 `retry_of_task_id`，同时清除 provider/pipeline 检查点。若失败码为 `PROVIDER_SUBMIT_AMBIGUOUS` 或 `RECOVERY_EXHAUSTED`，禁止该路径；须使用 `provider-resumes` 在同一任务上续跑（绑定已知远端任务 ID，或显式确认重新提交）。使用幂等键避免网络重试造成重复执行。供应商临时 URL 仅作为传输地址，不作为长期引用。

## 提示词与评估

- 提示词模板有名称和版本号；每个任务记录实际模板版本。
- 系统约束、用户内容和引用资产信息分区传入，避免用户输入覆盖输出格式要求。
- 建立小型固定评估集，覆盖不同题材、角色数、分镜数、中文对白、格式错误和局部修改指令。
- 评估结构合法率、设定引用完整度、镜头差异度和人工可编辑性；画面质量由人工样例审阅，不仅用调用成功率衡量。

## 诚实展示

界面区分 AI 生成、用户编辑和预置演示内容。若某功能使用缓存或 mock，必须在对应结果处清楚标注，并保证普通交互不会误导用户相信它执行了实时模型调用。

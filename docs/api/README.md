# API 契约与需求变更流程

## 契约规则

- `openapi.yaml` 是 HTTP API 的唯一人工维护契约源，使用 OpenAPI 3.1.0。
- 首轮核心工作区需求已在 PRD 标记为 `confirmed`；连载季策划、连续剧情线、章节摘要和阅读页为 `deferred`。
- 需求、数据结构或交互变化，先更新需求文档和 YAML，再实现前后端。
- FastAPI 路由、Pydantic schema 和前端类型都是契约的实现/派生产物，不另行定义接口事实。
- 不在浏览器与模型供应商之间直连；模型凭据和供应商协议属于后端内部实现，不暴露到公开 API。
- API 使用 `/api/v1` 前缀。已发布的字段语义不能静默改变；破坏性改动必须评估迁移并升主版本或提供兼容期。

## 需求状态与进入开发的门槛

PRD 中每项需求分配稳定 ID，并标记为以下状态之一：

- `proposed`：待讨论，不进入开发。
- `confirmed`：用户问题、交互结果和验收条件已确认，可进入接口设计。
- `deferred`：已讨论但不在当前版本。
- `rejected`：有记录地不采用。

只有 `confirmed` 需求可以成为当前版本的正式业务 API 操作或 schema。每个业务 OpenAPI operation 使用 `x-requirement-ids` 关联需求 ID；不承载产品能力的 `System` 运维操作（例如 health/version）可以不关联需求，但必须有契约和自动检查。需求变更必须同时更新对应验收条件和接口定义。核心预制作工作流契约现已冻结；扩展能力需先更新需求和契约再实现。

## 每项需求的确认清单

进入接口设计前，需求至少要说明：

1. 谁触发操作、要完成什么用户目标。
2. 前置条件和归属资源，例如项目、集数或分镜。
3. 输入字段含义、必填性、约束和默认值。
4. 成功结果及用户下一步能看到什么。
5. 失败、重试、取消和重复提交的行为。
6. 数据保留、版本影响和权限边界。
7. 可观察、可手工验证的验收条件。

含义未确定的字段不要提前放进 schema；在 PRD 中标为待确认，并避免用无约束的 `additionalProperties` 逃避设计。

## YAML 先行的交付顺序

1. 提出需求：在 PRD 中写明问题、用户流程、范围、非目标和验收条件。
2. 确认需求：将状态改为 `confirmed`，记录需求 ID；未确认项不进入本次实现。
3. 设计契约：更新 `openapi.yaml` 的路径、参数、请求/响应 schema、错误码、异步行为和需求关联。
4. 契约评审：检查语义、命名、一致性、兼容性、鉴权/数据归属和失败处理；产品与技术边界均通过后冻结本项契约。
5. 生成并实现：从 YAML 生成前端类型；实现 FastAPI schema/路由和前端调用，不手写重复 TS 接口。
6. 验证一致性：校验 OpenAPI、生成前端类型、检查路由清单并执行以 YAML 为输入的契约测试。FastAPI 自动导出的规范只用于实现核对，不覆盖 YAML 源契约。
7. 演示验收：依照需求验收条件走通真实用户路径；更新完成状态和已知限制。

## 必需的自动检查

- YAML 解析及 OpenAPI 3.1 规范校验。
- OpenAPI lint：operationId 唯一、路径命名一致、响应和错误结构完整、无悬空 `$ref`。
- 从 YAML 生成 TypeScript 类型；生成结果不产生未提交差异。
- 路由清单检查：契约中每个 operation 都有实现或明确标记为暂缓；不允许无契约的公开路由。
- 契约测试以 YAML 为输入，覆盖成功响应、主要校验错误、未找到资源和异步任务状态。
- 契约测试/静态比对发现 FastAPI 实现与 OpenAPI 语义不一致时阻止合并；FastAPI 自动导出的文档不能反向改写 YAML。
- 对异步生成确认任务 ID、状态枚举、轮询终态、重试和重复提交语义。

## 变更控制

- **兼容性新增**：可选字段、可选操作或新响应字段，更新 YAML、需求、测试和类型。
- **兼容性风险**：新增必填字段、收窄枚举、改变默认行为或资源状态含义，需明确调用方影响和迁移方案。
- **破坏性变更**：删除/重命名字段或操作、改变字段类型/语义、改变响应封套。记录版本策略、迁移步骤和弃用时间，不能只改 YAML 后直接上线。
- **实现偏离契约**：先判断契约遗漏还是实现错误；由需求负责人确认后修改唯一源，禁止仅更新运行时实现。

## 评审模板

每个 API 变更至少附上：

- 关联的 `confirmed` 需求 ID。
- 用户流程或调用示例。
- 请求和成功响应示例。
- 主要错误与异步状态示例。
- 兼容性说明。
- 契约校验/契约测试结果。

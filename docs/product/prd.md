# 产品需求文档

## 目标

让个人连载漫画创作者能够在一个作品中复用设定、创作并审阅分镜、生成和局部修改静态画格，逐步完成可阅读、可导出的漫画。当前已确认交付聚焦于连载工作台的故事、设定、分镜和画格阶段；成稿页排版与独立文字层仍按下方长期需求门禁推进。

## 用户与使用情境

主要用户是独立漫画作者，以及希望将小说、网文或剧本改编为静态漫画的个人创作者。用户持续创作一部或多部作品，需要跨话管理人物、世界观和剧情连续性；希望 AI 加速制作，但保留对故事、对白和画面的控制权。

## 核心路径

1. 创建作品并输入创意、故事正文、题材、画风和连载目标。
2. 生成角色与场景设定，编辑并确认核心设定。
3. 基于故事和已确认设定生成结构化分镜脚本。
4. 编辑分镜顺序、镜头信息、对白和画面描述。
5. 为单格或整页生成画面，查看任务进度和失败原因。
6. 对单格重绘或修改，保留历史版本并确认最终结果。
7. 当前可预览并导出画格长图、分页图片和制作资料；长期目标是在独立文字层与成稿页布局中完成可阅读漫画。

## 功能需求

核心漫画创作工作区与连载层（季策划、伏笔、话摘要与续写上下文、阅读页、作品设定集）需求均为 `confirmed`。需求 ID 在评审和实现期间保持稳定。API 资源名仍为 Project / Episode；产品文案使用「作品 / 第 N 话」。

### 账户与模型工作台

- **AUTH-01** (`confirmed`)：用户可通过邮箱一次性验证码登录或注册，也可通过 GitHub OAuth 登录；不要求设置密码。
- **AUTH-02** (`confirmed`)：每个请求只能访问当前账户拥有的项目和资产；其他账户的资源统一返回 `404`。从单账户试点升级时，将既有项目和生成任务归属回填到原账户。
- **AUTH-03** (`confirmed`)：用户可设置账户昵称；头像使用 GitHub 账户头像并在设置页展示。
- **AUTH-04** (`confirmed`)：验证码短时有效、一次性使用、限制错误次数和发送频率；请求验证码时不暴露邮箱是否已注册，验证码只以带 pepper 的摘要保存。
- **AUTH-05** (`confirmed`)：账户可查看邮箱和 GitHub 登录身份；只有保留至少一种其他登录方式时才可解除身份。不同 provider 的身份不得仅凭相同邮箱自动合并。
- **AUTH-06** (`confirmed`)：浏览器认证使用 HttpOnly Cookie 会话与 CSRF 校验；服务端兼容 opaque Bearer session，浏览器不将 token 持久化到 localStorage。
- **MODEL-01** (`confirmed`)：用户可以配置 OpenAI 兼容文本模型的公网 HTTPS Base URL、模型 ID 与 API Key，并测试连通性；API Key 在服务端加密保存且永不回显。
- **MODEL-02** (`confirmed`)：用户可以选择 Qwen Image 官方支持型号并发起异步图像生成；任务状态和生成结果可在刷新后恢复，图片经服务端持久对象存储保存（见 INFRA-02）。
- **MODEL-03** (`confirmed`)：用户可按账户配置 Qwen Image API Base URL；服务端限制为公网 HTTPS，并使用该地址提交与轮询图像任务。

### SaaS 身份认证方向（待契约确认）

- **AUTH-07** (`deferred`)：账户可主动把新的邮箱或第三方身份绑定到既有账户；绑定流程需要已登录账户确认，禁止仅凭相同邮箱自动合并账户。
- **INFRA-01** (`confirmed`)：Redis 为邮箱验证码 TTL、请求限流和异步生成任务提供短期状态与调度；PostgreSQL 保留账户、身份、会话、任务状态、任务结果和错误等持久事实。
- **INFRA-02** (`confirmed`)：生成图像经 `ObjectStore` 持久化（本地目录或 S3 兼容对象存储，生产为腾讯云 COS，见 [ADR-004](../technical/decisions/ADR-004-object-storage-cos.md)）；业务侧以资产 ID / 对象键引用。`GET /assets/{asset_id}` 在校验账户所有权后以 API 代理流返回字节（私有桶，不默认公网直链）。**生产已切流**（里程碑 `v0.1.0-storyboard`）。导出制作包一期仍可落在数据库；迁出对象存储、正式镜像重建与密钥轮换为同需求运维/后续切片。应用更新默认冻结，见 `.harness/status.md`。

邮箱验证码主登录代表用户可访问该邮箱，不是 MFA，也不具备抗钓鱼能力。首版邮件服务通过 SMTP 配置，开发环境可使用 Mailpit。

### 项目与故事

- **PROJ-01** (`confirmed`)：用户可以创建、列出和打开自己的故事项目（作品）。
- **PROJ-02** (`confirmed`)：用户可以修改项目标题、梗概、题材、画风和画幅。
- **PROJ-03** (`confirmed`)：用户可以删除项目；删除前明确提示影响范围。
- **PROJ-04** (`confirmed`)：用户可以编辑作品设定集：世界观、画风规则、作品级负向提示词与可选 style seed；画风规则与负向提示词在图像生成时与账户/系统配置合并。可选设置封面资产；未设置时列表使用派生缩略图。
- 项目保存梗概、题材、画风、画幅、设定集字段和最近更新时间。
- 支持编辑故事梗概；后续生成应使用当前已保存版本。

### 连载策划与连续创作

- **SERIAL-01** (`confirmed`)：用户可基于创意梗概、题材、画风、受众与目标话数发起 AI 季策划，审阅并确认标题、世界观、角色草案、话大纲与伏笔后创建作品。
- **SERIAL-02** (`confirmed`)：用户可以在作品中查看、新增、编辑和标记回收伏笔；未回收伏笔进入续写上下文。
- **SERIAL-03** (`confirmed`)：用户可以为已创作的话生成或更新摘要；续写下一话或生成分镜时注入前情摘要与未回收伏笔。生成第 N 话（N>1）的分镜脚本或故事流水线前，第 N-1 话必须已有非空摘要，否则拒绝并提示先生成摘要。
- **SERIAL-04** (`confirmed`)：用户可以在独立阅读页按顺序浏览某一话的画格与对白，并在话之间导航。

### 角色与场景设定

- **STORY-01** (`confirmed`)：用户可以在项目中创建、查看和编辑多个故事单元（话）；工作区支持切换与新建。
- **ASSET-01** (`confirmed`)：用户可以从项目故事生成结构化角色档案，明确区分 AI 起稿与手动设定，编辑并确认角色设定。角色资产为作品级、跨话复用。用户可对单个角色重生文本设定与/或参考图，也可批量补齐缺失参考图。默认以追加方式补充新人（规范化同名已存在则不覆盖；不删除未提及的旧角色）。显式「替换整队」时才允许覆盖并移除未出现在新结果中的旧角色，并清理分镜中失效的角色引用。角色参考图可单独锁定为定妆照；锁定后重新生成角色草稿不得清空或替换该参考图；分镜画面生成应对已锁定且有参考图的出场角色附带一致性约束（含外观描述；供应商支持时附带参考图）。
- 从故事生成结构化场景档案。
- 用户可以编辑档案并标记为草稿或已确认。
- 已确认档案在生成分镜和画面时作为上下文引用。
- 可为档案关联参考图；系统不宣称参考图能保证绝对一致。
- **ASSET-02** (`confirmed`)：用户可以查看、编辑和确认场景档案，并将其作为分镜画面生成上下文。场景资产为作品级、跨话复用。用户可对单个场景重生文本设定与/或参考图，也可批量补齐缺失参考图。默认追加新场景且不删除未提及的旧场景；显式「替换整队」时才允许覆盖并清空分镜中失效的场景引用。

### 分镜脚本

- **SB-01** (`confirmed`)：用户可以基于故事与已确认设定生成有序分镜草稿。作品已有角色库时，本话默认复用该库生成分镜，不得默认整队重生角色。非首话须满足 SERIAL-03 的摘要前置。
- **SB-02** (`confirmed`)：用户可以编辑分镜字段并调整分镜顺序。
- **SB-03** (`confirmed`)：用户可以在分镜列表中新增和删除单格，并查看其草稿、待审阅或已确认状态。
- 根据故事、已确认设定和用户偏好生成有序分镜列表。
- 每格至少包含：序号、场景、镜头景别/角度、构图描述、角色动作、情绪、对白、画面提示词和剧情作用。
- 用户可以编辑字段、调整顺序、添加/删除分镜。
- 重新生成分镜脚本前提示将影响哪些现有内容；保留可恢复版本。

### 画面生成与编辑

- **GEN-01** (`confirmed`)：用户可以为单格发起图像生成或重绘，并保留旧版本。
- **GEN-02** (`confirmed`)：用户可以查询异步生成任务状态和结果。
- **GEN-03** (`confirmed`)：用户可以将失败任务作为新任务重试。若失败码表明远端图像任务可能已创建（`PROVIDER_SUBMIT_AMBIGUOUS` / `RECOVERY_EXHAUSTED`），禁止清除 checkpoint 的普通重试；须走供应商续跑（绑定已知远端任务 ID，或显式确认重新提交）。
- **GEN-04** (`confirmed`)：用户可以查看单格图像历史并选择当前使用版本。
- **GEN-05** (`confirmed`)：作品尚无任何角色时，默认禁止为分镜格发起画面生成（409 / `CAST_REQUIRED`），并引导先建立角色。用户可显式确认「试画」（请求体 `acknowledge_trial=true`）后旁路继续。作品已有角色库时，未挂角色 ID 的空镜可直接出图。工作室须常驻展示角色/定妆就绪提示；有角色但未确认或未定妆时允许出图，须醒目警告一致性风险。
- 用户可以生成单格图像；如果供应商支持，可生成整页布局。
- 每次生成形成独立任务和版本，页面明确显示排队中、处理中、成功或失败。
- 用户可以重试失败任务，或仅重绘选中的分镜。
- 修改提示词、引用角色/场景参考图后再重绘，不覆盖旧图。
- 画面生成供应商和具体参考图能力需在接入前验证。

### 每话厚度与可读叙事

- **SB-04** (`confirmed`)：新建故事单元默认分镜数量为 **8**（可选 4/6/8/10/12）；工作室「故事」阶段梗概输入上限与契约对齐（不少于 2000 字展示空间），避免默认把一话压成极短预告片。
- **SB-05** (`confirmed`)：分镜对白字段编辑上限与契约一致（最长 4000）；分镜画布须展示本话梗概摘要，便于作者先审字再出图。

### 审阅与导出

- **EXP-01** (`confirmed`)：用户可以将故事单元（一话）导出为竖向条漫长图 PNG、按页高自动分页的 PNG ZIP，或制作资料 JSON。分页 ZIP 内含 `page-01.png`…；**叠字规则**：该格槽已有 Lettering 时烘焙 Lettering，否则回退分镜 `dialogue` 占位气泡。下载文件名须带 `.png` / `.zip` / `.json` 后缀。
- **EXP-02** (`confirmed`)：用户可在作品总览发起「导出合集」：选择第 1–N 话，导出跨话多页 PNG ZIP 或一本多页 PDF。合集入口在作品总览（非单话工作室）。合集 PNG/PDF 叠字规则同 EXP-01。
- **产品文案**：EXP 为**制作预览 / 制作资料**导出（可烘焙气泡）。**成稿导出**属 **PUBLISH-01（`confirmed`，A3）**，与 EXP 双轨文案，不得混称。对外不得把 EXP 说成成稿导出。
- 分镜状态支持草稿、待审阅、已确认。
- 可预览分镜顺序、对白和画面。

## 非目标

- 多人实时协作、团队邀请、组织权限和复杂审批。
- 动态漫、动画或视频成片。
- 自训练基础模型或保证跨镜头完美一致。
- 专业级漫画排版软件的全部编辑能力（规划中的成稿层仅开放有限模板与气泡，见下节）。
- 在首版引入多 Agent 编排平台。
- 公开读者社区、推荐分发和未经授权的作品公开链接；私密、可撤销的评审链接须单独定义权限和内容保护需求。

## 成稿层阶段 A1：页与竖条排版（`confirmed`）

> 分层见 [roadmap-complete-comic.md](roadmap-complete-comic.md)。屏幕流见 [user-flows.md](user-flows.md)。契约见 `docs/api/openapi.yaml`（Layout / Page / PageSlot）。  
> **LETTER / PUBLISH-01 见阶段 A2、A3（均已 `confirmed`）。本 A1 切片仅页布局，不含字效与成稿导出实现叙述。**

产品方向：个人连载静态漫画工作台。L1 已交付；A1 在其上叠加可持久化竖条页；A2 叠加独立字效，不推翻 Studio 主路径。

### 规划决策（钉死）

- EXP = 制作预览/资料；PUBLISH = 成稿合成导出；双轨文案，不得混称。
- 成稿对象：`Page` / `PageSlot`（引 `PanelImageVersion`）+ `LetteringObject`（A2）；重绘 Panel 默认保留页布局与字效。
- SaaS MVP：个人账户 + 多作品 + L1 + 阶段 A；团队/社区不做。
- 计费叙事不阻塞 PAGE / LETTER 实现。

### 阶段 A1 — 页与排版（已确认，可实现）

- **PAGE-01** (`confirmed`)：用户可为某一话创建有序「页」（条漫段落）；每页含一个或多个格槽位，引用本话 Panel 的图像版本（`image_version_id`）。无布局时可一键从当前分镜顺序生成默认竖条页（每格一槽，默认同属一页）。
- **PAGE-02** (`confirmed`)：MVP **仅竖条漫**模板（`vertical_strip`）；可调槽位显示高度与槽间距；固定网格页漫不在本切片。
- **PAGE-03** (`confirmed`)：用户可调整页内槽顺序、高度与间距；用户选定某格新图像版本后，默认将该格已挂槽位改挂新版本并**保留**页序与几何；分镜增删格时须提示同步，不得静默丢弃用户调过的间距。

**验收**：

1. 本话有画格时，可生成并持久化默认竖条布局；刷新后布局仍在。  
2. 可调整槽序/格高/间距并保存；整话成稿预览与 Studio 制作态可区分。  
3. 在 Studio 重绘并选定新版本后返回成稿，页序与几何保留，槽位显示新图。  
4. 账户隔离：不能读写他人话的 layout。  
5. 0 画格时不能 bootstrap；部分无图格允许占位。

### 阶段 A2 — 字效（已确认，可实现）

> 屏幕流见 [user-flows.md · 阶段 A2](user-flows.md)。契约见 OpenAPI `Lettering` tag。  
> **A2 不含 PUBLISH 产品入口**；成稿预览叠字即可，正式成稿导出属 A3。

**MVP 决策（钉死）**

- 对象类型仅两种：`speech_bubble`（对白气泡）、`narration`（旁白条）。
- **挂在 PageSlot**（跟格走）；不做页级游离字效。
- 几何相对槽位：`x_pct` / `y_pct` / `width_pct`（0–100）；可选 `tail`（`none` | `bottom_left` | `bottom_right` | `top_left` | `top_right`）。
- 样式 MVP：白底圆角气泡 / 旁白条；`font_size` 为 `sm` | `md` | `lg`。不做人名框、爆炸泡、自定义字体上传。
- **成稿层对白真源为 Lettering**；Studio 分镜 `dialogue` 仍为制作态字段（脚本/种气泡来源）。
- **主编辑面**：工作室「制作预览」条漫（审图同一面）；成稿排版页以 **PAGE 页结构**（槽序/格高/间距）为主，字效为次要或只读引导。
- **叠字显示**：有 Lettering 用 Lettering；无则显示分镜对白占位（须可区分「未落成字效」）。Studio 画布卡、制作预览、EXP 烘焙遵循同一规则。
- 「从分镜生成气泡」：入口在工作室制作预览；对无字效且分镜对白非空的槽生成默认 `speech_bubble`；不覆盖已有字效，除非显式 `replace_existing`。无布局时先 bootstrap 再种。
- 重绘并换图版：默认**保留**该槽 Lettering（与 PAGE-03 一致）。
- 成稿预览：DOM 叠字，**不**写回图像资产；不提供「导出成稿」入口（A3）。EXP 可烘焙叠字但仍称制作预览。

- **LETTER-01** (`confirmed`)：用户可为某一槽添加、编辑、删除气泡或旁白文字对象；文本、几何与样式持久化，与底图分层；一槽可有多个对象并有序。
- **LETTER-02** (`confirmed`)：修改字效文案或样式不要求重绘底图；预览立即反映变更。栅格合成进「成稿导出」属 **PUBLISH（A3）**；EXP 制作预览可烘焙叠字但不改称成稿。
- **LETTER-03** (`confirmed`)：字效**主编辑入口**为工作室制作预览条漫；成稿排版不作为学气泡的第一课。无布局时，种气泡流程可自动生成默认竖条页。

**验收**：

1. 有布局的话可对槽增删改字效；刷新后字效仍在。  
2. 工作室制作预览可「从分镜生成气泡」并为有对白的空槽生成默认气泡；已有字效默认不被覆盖。  
3. 工作室条漫/制作预览可见字效叠层；改文案后无需重绘即可看到新字。  
4. Studio 重绘并选定新图版后，该槽字效仍在。  
5. 账户隔离：不能读写他人槽的字效。  
6. 无布局时不能直接种字效（须先 bootstrap，可并入种气泡流程）；删除槽时级联删除其字效。  
7. 无 Lettering 时显示分镜对白占位且可区分于已落成字效；有 Lettering 时不再用分镜对白抢显示。

### 阶段 A3 — 成稿导出（PUBLISH-01 `confirmed`；PUBLISH-02 仍 proposed）

> 屏幕流见 [user-flows.md · 阶段 A3](user-flows.md)。契约见 OpenAPI `Publish` tag。

**MVP 决策（钉死）**

- 入口文案：**导出成稿**（成稿排版页为主）；不得出现在「制作导出」菜单内。
- 合成真源：本话 **Page / PageSlot 顺序与几何** + **Lettering**。无布局则 409，引导先生成竖条页。
- 叠字：仅烘焙 Lettering；**不**用分镜 `dialogue` 回退（与 EXP 区分）。无字效的格只出底图。
- 格式 MVP：`png`（按槽序竖条长图）、`png_zip`（按布局页分页）、`pdf`（多页，一布局页一页）。CBZ 不做。
- 图像：槽位挂载的图像版本（与成稿预览一致）；缺图槽占位灰底。
- 下载文件名须带后缀，并体现「成稿」（如标题-成稿.png）。

- **PUBLISH-01** (`confirmed`)：用户可将本话导出为成稿 PNG 长图、按布局页的 PNG ZIP，或 PDF；产品文案与 EXP 区分；合成吃 Page + Lettering。
- **PUBLISH-02** (`proposed`)：只读分享以私密、可撤销为优先；公开免登录链接另确认；≠ 公开社区。本切片不实现。

**验收（PUBLISH-01）**：

1. 有布局的话可发起成稿导出；无布局 409 且不生成文件。  
2. 长图 / ZIP / PDF 槽序与成稿预览一致；有字效处可见烘焙字；无字效处无分镜对白冒充。  
3. 改 Lettering 后再次导出反映新字，无需重绘底图。  
4. 工作室「制作导出」文案与成稿入口可区分。  
5. 账户隔离：不能下载他人成稿资产。

### SaaS 产品面（阶段 C，不抢 A）

- **AUTH-07** (`deferred`)：设置页主动绑定身份；禁止仅凭同邮箱静默合并。
- 存储以 **INFRA-02** 为准；成稿导出契约另立，不扩大 INFRA-02 切片。
- 收费前：成本可见、额度/限流、失败重试计费、备份恢复、账户数据导出与删除。

### 长期成功信号

- 从已有分镜走到「像一本漫画」的可读成稿并导出。
- 改对白或重绘一格，不必重做整话排版。
- 同一作品可继续第二话并复用设定与资产。
- 对外分清：已交付的分镜/画格/页布局 vs 字效（A2 交付前不得宣传字效已上线）vs 成稿导出（A3 交付前不得宣传成稿导出已上线）。

## 质量要求

- 模型密钥仅保存在服务端。
- GitHub OAuth Secret、会话凭据和模型 API Key 不暴露给浏览器；自定义文本端点需阻止回环、私网和云元数据地址。
- 异步图像任务可以恢复查询；一次分镜失败不影响其他分镜。
- 用户编辑内容和历史生成结果在刷新后仍可恢复。
- 错误信息清楚说明问题及可执行的下一步。
- 导出内容与当前已确认分镜一致。

## 产品成功信号

- 用户能从故事输入走到可预览、可导出的分镜成果。
- 用户可以指出并修改具体分镜，而不必重做整页。
- 角色和场景设定在后续生成中可复用。
- 演示者能明确区分真实模型能力、系统处理和人工修改。
